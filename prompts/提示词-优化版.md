# 抖音横屏知识短片 · Remotion 提示词（优化版）

用法：**第 0 步「项目设定卡」只发一次**（和第 1 步一起发，或者直接贴进仓库的 `CLAUDE.md`），后面第 1–4 步按顺序发，每一步都等你确认了再往下走。原版里每一步都在重复的规格、水印、字体、自查方法都收进了设定卡，后面的步骤只写这一步新增的要求。

---

## 第 0 步 · 项目设定卡

```
【主题】：________
【时长】：约 ___ 秒（建议 120–150 秒，同类爆款大多在 2 分到 2 分半之间）
【规格】：1920×1080 横屏，30fps，无口播，屏幕上的字幕就是全部文字
【画面】：全部用 Remotion 代码画（形状、光、线条、粒子、文字），不用实拍、图库或 AI 生成图
【字体】：思源黑体 / 思源宋体（Noto Sans SC / Noto Serif SC），主字幕不小于 64px，放在画面中部
【音乐】：BGM 用 assets/music/bgm_source.mp3（168 BPM，44.6 秒）。
        运行 python3 scripts/bgm.py --seconds <总时长> --drop <高潮秒数>，拼接出 public/audio/bgm.wav，
        同时生成卡点表 src/data/beatmap.json。所有换屏、动作、音效都从这张表里取时间。
【音效】：全部用代码合成 wav，不用音效素材
【水印】：右上角固定文字「肆号静匣Logos」，外面包一圈细空心方框。字号约 22px，线宽 1px，透明度约 35%。
        水印放在镜头运动之外，全程不动、不跟着缩放。字幕和其它动画文字都不要进入这个区域
【安全区】：底部 10% 留给抖音界面，不放主字幕

风格规矩（学的是 Vibe 知识大赏爆款的共同做法，每一步都要遵守）：
1. 先演后讲：开头先演一个具体的小东西或反常识的现象，片名卡不放在开头
2. 一个物件贯穿全片：新概念尽量让这个物件变形来表达，不另起新图形
3. 字幕说到什么，画面就演什么：说到的数字和过程，画面上都要真的出现
4. 叙事顺序：钩子 → 实证 → 命名概念 → 落到观众自己身上 → 讲机制 → 金句；先讲现象，再讲概念
5. 结尾回到开头：开头的画面再出现一次，但意思已经变了
6. 层级：图形 > 主字幕 > 附着标签 > 注释。每屏只讲一个观点
7. 有静有动：观众读字时主体可以停住，但画面要有呼吸（缓慢漂移、光、粒子），镜头完全静止不超过 3 秒；
   全片只有 3–5 处大动作（字砸下来、全屏变化、重音效），留给主题词和关键句
8. 不用：霓虹色、玻璃拟态、HUD 网格、故障闪烁、emoji
9. 事实要有出处；推测要标「示意」「据说」；片尾列出出处
```

## 第 1 步 · 方案（不写代码）

```
先不要写代码，也不要写完整稿，只给我一份方案：
1. 选题：用一句话说清观众看完能带走的那一个观点，再写一个反常识的切入点
2. 主线问题：一个能让观众带着看完的问题，片尾要能回答
3. 开头三个备选，标出你推荐哪一个。每个都写出前 5 秒的字幕和画面动作，并说明它落在音乐的哪个位置（前奏、铺垫还是 drop）
4. 全片结构：每节用一句话说讲什么，估一下时长，并标出主线问题或主题词落在第几秒（这就是 --drop 的值）
5. 视觉方向两到三个，每个写清：底色、强调色、贯穿全片的物件或形状、这个物件在全片里怎么变化。
   可以参考「鎏金暗场」「夜曲」「寓言」三种常见画风（见文末附录），只写代码做得出来的画面
6. 需要我核实的事实，以及平台风险：AI 生成内容标识、BGM 版权、敏感表述
```

## 第 2 步 · 字幕稿（可以运行 bgm.py，不写 Remotion 代码）

```
我选：开头 __ + 视觉方向 __。

先运行 scripts/bgm.py 拿到卡点表，再写完整字幕稿。格式用表格，一行一屏：
| 屏号 | 时间码 | 字幕 | 画面动作 | 音效 | 卡点 |

要求：
1. 每屏一句，不超过 15 个字。按每秒不超过 4 个字算时长，每屏至少 2 秒；读不完的拆成两屏
2. 重点词用【】标出来，后面做成高亮；每屏最多一个
3. 换屏时间对齐卡点表里的 bars（误差不超过 2 帧）。读字时间优先：时间不够就推到下一个小节，不要为了卡点提前切
4. 卡点列：标出全片 3–5 处重卡点（主题词砸下来、主线问题、核心反转、金句），放在 drop 或 accents 上
5. 画面全程在动，同一个画面最多挂两屏字幕；贯穿物件要跟着论点一起变化
6. 核实没通过的事实不要写进去
7. 最后附上：总字数、总时长、重卡点清单，以及你最没把握的三句
```

## 第 3 步 · 30 秒样片

```
用 Remotion 搭项目。先只做前 30 秒左右（开头加第一节）当预览：
1. 字幕定稿存成 src/data/subtitles.ts，每屏写清开始帧、结束帧、文字、重点词。
   画面、音效、卡点的时间都从这个文件和 beatmap.json 里取，以后改字幕只改这一个文件
2. 每节写成一个组件；贯穿物件单独做成一个组件，各节复用
3. 整片当成一个连续镜头来拍：
   - 场景之间用推近、拉远、平移过渡，不要原地换内容，也不要像 PPT 那样翻页
   - 每节换一次场景，背景、光线、景别至少变一样
   - 贯穿物件是主角，要长大、变形、填满画面，不能一直是背景里的小点
   - 镜头运动从小节线（bars）开始，落定在底鼓（kicks）上；重卡点配全屏级别的画面和最响的音效
4. BGM 用 public/audio/bgm.wav，音量比音效低；重音效响起时，BGM 自动压低 4–6dB，持续约 0.5 秒
5. 渲染成 mp4 以后自己先检查一遍：
   - 每 2 秒抽一帧拼成一张联系表，检查字有没有被挡、有没有出画、有没有进水印区、有没有还没读完就切走的屏
   - 对每个重卡点，抽它前后各 3 帧，确认动作确实落在拍上
   修好以后再交给我
6. 交给我：预览 mp4 的路径、渲染命令、你自己发现并修掉的问题
```

## 第 4 步 · 完整片

```
预览风格定了，按这个风格做完整片：
1. 按字幕定稿把剩下的各节全部做完，镜头、转场、物件变化都延续预览的做法。预览部分已经改好的地方不要动
2. 每节之间连续过渡，不用黑场；每节至少换一次景别或背景
3. 主线问题在结尾回收：开头抛出的问题，片尾给出答案，画面上要和开头呼应
4. 音效按时间轴补全。整片响度约 -14 LUFS，真峰不超过 -1dBTP；重卡点上的音效最响；不能有意外的静音
5. 分段渲染，渲完合成一个完整的 mp4
6. 交片前自查：
   - 每 2 秒抽一帧检查遮挡、出画、水印区、没读完就切走
   - 用 ffmpeg freezedetect 找出静止超过 3 秒的段落，补上动作
   - 用 silencedetect 和 ebur128 检查静音段和爆音
   - 重卡点逐个核对，确认画面落在拍上
7. 交给我：成片路径、总时长、每节怎么接到下一节（每节一两句话）、重卡点清单（时间、字幕、动作）、自查时发现并修掉的问题
```

三种常见画风：
- **鎏金暗场**：近黑底，象牙白 #E8E3D9，金 #DDBD74，朱红 #D9583C；漂浮的失焦尘埃，四角压暗；字幕用粗宋，逐字由虚变实
- **夜曲**：蓝黑夜空加细小星点，白 #F8F9F8，金 #F8D893，冰蓝 #64E3F6，玫红 #E84B75；细宋，字距大，整行淡入；适合讲底层、抽象的知识
- **寓言**：每场一幅扁平的代码插画，暖白 #FFFAEB，金 #EEC672，关键词用红 #FC593F；适合讲心理和行为

共同做法：先演后命名；一个物件贯穿全片；结尾回到开头，但意思变了；几乎没有硬切；读字时画面相对安静（拆解里约三分之一的帧是静止的）。

## 附录 · 这首 BGM 的卡点结构

实测数据，写在 `scripts/bgm.py` 里：

| 段落 | 原曲时间 | 适合放什么 |
|---|---|---|
| 前奏 | 0–4.46s | 钩子的第一个画面 |
| 铺垫 A | 4.46–20.16s | 钩子和实证，动作克制 |
| 断奏蓄力 | 20.16–21.58s | 低音消失，适合留白，或让主线问题停在屏幕上 |
| **drop** | **21.58s** | **全片最重的一个卡点：主题词或主线问题砸下来** |
| 高潮 B | 21.58–38.70s | 正文；每 5.7 秒一个乐句起点（accents），可以挑来做换节 |
| 尾段 | 38.70s 起 | 结尾回扣和金句，最后 2.5 秒淡出 |

- 拍长 0.357 秒（约 10.7 帧）；底鼓每 0.713 秒一下（约 21 帧），适合做小脉冲
- 一个小节 1.43 秒（约 43 帧），适合换屏；一个乐句 5.7 秒（约 171 帧），适合换节
- 成片比 44.6 秒长时，脚本会按乐句把铺垫段和高潮段循环拼接，接口都在重拍上，并做 30ms 交叉淡化；`--drop` 用来指定 drop 落在第几秒
