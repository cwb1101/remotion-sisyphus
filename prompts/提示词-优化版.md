# 抖音横屏知识短片 · Remotion 提示词（四步版）

在新窗口里按顺序发送第 1 到第 4 步，每一步都等确认后再发下一步。
第 1 步已经包含全部设定，包括画风参考和音乐处理方法，新窗口不需要任何前情。发第 1 步时**把 BGM 音乐文件一起附上**。

---

## 第 1 步 · 设定 + 方案

```
我要用 Remotion 做一条抖音横屏知识短片。下面是全片设定，后面每一步都要遵守。

【主题】：________
【时长】：约 ___ 秒（建议 120–150 秒）
【规格】：1920×1080 横屏，30fps，无口播，屏幕上的字幕就是全部文字
【画面】：全部用 Remotion 代码画（形状、光、线条、粒子、文字），不用实拍、图库或 AI 生成图
【字体】：思源黑体 / 思源宋体（Noto Sans SC / Noto Serif SC），主字幕不小于 64px，放在画面中部
【音乐】：BGM 是我附上的音乐文件，保存到 assets/music/，全片的换屏、动作、音效都要卡这首曲子的拍点
【音效】：全部用代码合成 wav，不用音效素材
【水印】：右上角固定文字「肆号静匣Logos」，外面包一圈细空心方框，字号约 22px，线宽 1px，透明度约 35%。
        水印不跟着镜头运动或缩放，全程固定。字幕和其它动画文字都不要进入这个区域
【安全区】：底部 10% 留给抖音界面，不放主字幕

【风格规矩】（参考「Vibe 知识大赏」类爆款的共同做法）
1. 先演后讲：开头先演一个具体的小东西或反常识的现象，片名卡不放在开头
2. 一个物件贯穿全片：新概念尽量让这个物件变形来表达，不另起新图形
3. 字幕说到什么，画面就演什么：说到的数字和过程，画面上都要真的出现
4. 叙事顺序：钩子 → 实证 → 命名概念 → 落到观众自己身上 → 讲机制 → 金句；先现象，后概念
5. 结尾回到开头：开头的画面再出现一次，但意思已经变了
6. 层级：图形 > 主字幕 > 附着标签 > 注释。每屏只讲一个观点
7. 有静有动：读字时主体可以停住，但画面要有呼吸（缓慢漂移、光、粒子），镜头完全静止不超过 3 秒；
   全片只有 3–5 处大动作（字砸下来、全屏变化、重音效），留给主题词和关键句，并且都落在音乐重拍上
8. 不用：霓虹色、玻璃拟态、HUD 网格、故障闪烁、emoji
9. 事实要有出处；推测要标「示意」「据说」；片尾列出出处

【画风参考】（选视觉方向时从这里出发，也可以混搭）
- 鎏金暗场：暖近黑底，象牙白 #E8E3D9，金 #DDBD74，朱红 #D9583C；漂浮的失焦尘埃，四角压暗；粗宋字幕逐字由虚变实，重点词染金
- 夜曲：蓝黑夜空加细小星点，白 #F8F9F8，金 #F8D893，冰蓝 #64E3F6，玫红 #E84B75；细宋，字距大，整行淡入；适合讲底层、抽象的知识
- 寓言：每场一幅扁平的代码插画，暖白 #FFFAEB，金 #EEC672，关键词用红 #FC593F；适合讲心理和行为
- 爆款开头示例：骰子落地，问「运气，能被计算吗？」；鸟扑向假蛋，字幕「你的手机里，也有一颗」；
  逐字打出「床前明月＿」让观众心里先填空。结尾回扣开头，比如骰子回来了，背后多了一条钟形曲线

先分析音乐（只跑分析脚本，不写 Remotion 代码）：
用 librosa 测出 BPM、每一拍、底鼓重拍、小节（4 拍）、乐句（通常 16 拍），
并按能量和频谱变化分出段落：前奏、铺垫、蓄力、drop、高潮、尾段，标出 drop 在第几秒、曲子总长多少秒。
用一张表告诉我，每段写上原曲时间和适合放什么内容。

再给我一份方案：
1. 选题：用一句话说清观众看完能带走的那一个观点，再写一个反常识的切入点
2. 主线问题：一个能让观众带着看完的问题，片尾要能回答
3. 开头三个备选，标出你推荐哪个。每个都写出前 5 秒的字幕和画面动作，并说明落在音乐的哪一段
4. 全片结构：每节用一句话说讲什么，估一下时长；标出主线问题或主题词落在第几秒（drop 要对齐到这里），以及 3–5 处大动作的位置
5. 视觉方向两到三个，每个写清：底色、强调色、贯穿全片的物件，以及这个物件在全片里怎么变化。只写代码做得出来的画面
6. 需要我核实的事实，以及平台风险：AI 生成内容标识、BGM 版权、地图和敏感表述
```

## 第 2 步 · 字幕稿

```
我选：开头 __ + 视觉方向 __。

先把音乐拼好、做出卡点表，再写字幕稿（不写 Remotion 代码）：
1. 写一个脚本 scripts/bgm.py，参数是 --seconds <总时长> 和 --drop <drop 落在第几秒>；仓库里已经有的话直接用。
   - 成片比曲子长时，按乐句把铺垫段和高潮段循环拼接，接口都落在重拍上，做 30ms 交叉淡化
   - 调整铺垫乐句的数量，让 drop 尽量落在主线问题出现的那一秒
   - 尾段至少完整播 2.5 秒再淡出，开头 0.05 秒淡入，全程不能出现静音
   - 输出 public/audio/bgm.wav，以及 src/data/beatmap.json，里面用 30fps 的帧号记录：
     beats（每拍）、kicks（底鼓）、bars（小节）、phrases（乐句）、accents（高潮段的乐句起点）、sections（段落）、dropFrame
2. 按卡点表写完整字幕稿，格式用表格，一行一屏：
   | 屏号 | 时间码 | 字幕 | 画面动作 | 音效 | 卡点 |

字幕要求：
1. 每屏一句，不超过 15 个字。每秒不超过 4 个字，每屏至少 2 秒；读不完的就拆成两屏
2. 重点词用【】标出来，后面做成高亮；每屏最多一个
3. 换屏对齐 bars（误差不超过 2 帧）。读字时间优先：时间不够就推到下一个小节，不要为了卡点提前切
4. 卡点列：标出全片 3–5 处重卡点（主题词、主线问题、核心反转、金句），放在 drop 或 accents 上
5. 画面全程在动，同一个画面最多挂两屏字幕；贯穿物件要跟着论点一起变化
6. 核实没通过的事实不要写进去
7. 最后附上：总字数、总时长、重卡点清单，以及你最没把握的三句
```

## 第 3 步 · 30 秒样片

```
用 Remotion 搭项目。先只做前 30 秒左右（开头加第一节）当预览：
1. 字幕定稿存成 src/data/subtitles.ts，每屏写清开始帧、结束帧、文字、重点词。
   画面、音效、卡点的时间都从这个文件和 beatmap.json 里取，以后改字幕只改这一个文件
2. 每节写成一个组件；贯穿物件单独做成一个组件，各节复用；水印单独做成一层，放在镜头层外面
3. 整片当成一个连续镜头来拍：
   - 场景之间用推近、拉远、平移来过渡，不要原地换内容，也不要像 PPT 那样翻页
   - 每节换一次场景，背景、光线、景别至少变一样
   - 贯穿物件是主角，要长大、变形、填满画面，不能一直是背景里的小点
   - 镜头运动从小节线（bars）开始，落定在底鼓（kicks）上；重卡点配全屏级别的画面和最响的音效
4. BGM 用 public/audio/bgm.wav，音量比音效低；重音效响起时，BGM 压低 4–6dB，持续约 0.5 秒
5. 渲染成 mp4 后自己先检查一遍，修好再交给我：
   - 每 2 秒抽一帧拼成一张联系表，检查字有没有被挡、有没有出画、有没有进水印区、有没有还没读完就切走的屏
   - 每个重卡点抽前后各 3 帧，确认动作确实落在拍上
6. 交给我：预览 mp4 的路径、渲染命令、你自己发现并修掉的问题
```

## 第 4 步 · 完整片

```
预览风格定了，按这个风格做完整片：
1. 按字幕定稿把剩下的各节全部做完，镜头、转场、物件变化都延续预览的做法。预览部分已经改好的地方不要动
2. 每节之间连续过渡，不用黑场；每节至少换一次景别或背景
3. 主线问题在结尾回收：开头抛出的问题，片尾给出答案，画面上要和开头呼应
4. 音效按时间轴补全。整片响度约 -14 LUFS，真峰不超过 -1dBTP；重卡点上的音效最响；不能有意外的静音
5. 分段渲染，渲完合成一个完整的 mp4
6. 交片前自查：
   - 每 2 秒抽一帧，检查遮挡、出画、水印区、没读完就切走
   - 用 ffmpeg freezedetect 找出静止超过 3 秒的段落，补上动作
   - 用 silencedetect 和 ebur128 检查静音段和爆音
   - 重卡点逐个核对，确认画面落在拍上
7. 交给我：成片路径、总时长、每节怎么接到下一节（每节一两句话）、重卡点清单（时间、字幕、动作）、自查时发现并修掉的问题
```
